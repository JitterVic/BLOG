# 余笺设计规格

状态：已确认，待实现

## 1. 目标

在现有「首页 / 文章 / 关于」之外增加第四个一级入口「余笺」，用于收纳尚未必要写成文章的个人记录。内容可以是日常、项目、作品或随想，既支持短篇文字，也支持图片、作品预览和外部链接。

余笺不是社交动态流，也不是第二个文章列表。它是至知这本「摊开的笔记本」里较轻的一组记录：比文章自由，比动态更适合回看。

## 2. 已确认的产品决定

### 2.1 导航

一级导航为：

> 首页　文章　余笺　关于

「文章」承担完整、连贯、适合沉浸阅读的长文；「余笺」承担短记录、项目过程、作品展示和不必扩写成文章的想法。

### 2.2 内容类型

余笺固定使用四种类型：

- 日常：生活观察、近况和简短记录。
- 项目：正在进行或已经完成的项目记录。
- 作品：图片、设计、代码实验及其他可展示成果。
- 随想：不定期的想法、阅读触发的片段和未完成观点。

类型是筛选维度和元信息，不使用彩色标签系统，也不开放自由录入。这样可以保持界面可枚举、可扫描，避免退化为第二个标签云。

### 2.3 首页露出

首页仍以最新文章为第一视觉重点。在现有首页区块之后增加「近笺」区块，展示最近 2–3 条余笺，并提供「全部余笺」入口。

「近笺」使用现有线性列表和分隔线，不使用卡片、阴影或瀑布流。每一行展示日期、标题、简短摘要和类型；项目或作品可以额外显示图片数量或外部链接存在性，但不在首页展开媒体预览。

## 3. 余笺页面

### 3.1 页面结构

页面标题为「余笺」，导语为：

> 记下那些尚未必要成为文章的事。

导语使用 `--f-kai` 和现有导语字阶。其下是固定类型筛选：

> 全部　日常　项目　作品　随想

列表按年份分组，沿用 `PostRow` 的线性索引结构。URL 是筛选状态的唯一来源：

- `/notes`：全部余笺
- `/notes?type=project`：项目
- `/notes?type=work`：作品

具体类型值应在实现时统一定义，前台显示名称始终使用中文。

### 3.2 条目形态

每条余笺至少包含标题、正文、类型和日期；可选摘要、封面/媒体、外部链接。

- 普通短篇以标题、摘要和类型为主，保持低阅读负担。
- 项目和作品可以携带一张或多张图片、预览图及外部链接。
- 列表不直接承载完整正文，条目进入独立详情页后再阅读或查看媒体。
- 详情页沿用文章页的阅读宽度、宋体正文、楷体导语和标题共享转场。

独立详情页保证记录可分享、可被搜索引擎正确理解，也避免在列表中塞入过多内容。

## 4. 视觉与动效

### 4.1 视觉边界

余笺复用现有设计令牌、字体分工、线的两级制和响应式壳，不新增一套颜色或卡片组件。

- 类型使用黑体小字号文字元信息。
- 条目之间使用 `1px var(--line)` 分隔。
- 区块起始使用现有 `1px var(--ink)`。
- 标题、当前筛选和搜索命中可以使用已有荧光笔语义。
- 不使用社交产品常见的点赞、评论、分享计数、头像墙或无限滚动。

### 4.2 基础动效

新增动效必须服从 DESIGN.md §7 的克制原则，只在结构变化处提供反馈：

1. 首页进入余笺时，页面标题使用现有标题共享转场。
2. 余笺首次加载列表时，条目按时间顺序做一次极小位移与透明度显现；不做逐字、逐卡片或持续循环动画。
3. 类型筛选更新列表时，只使用短暂的透明度和小幅纵向位移，避免布局跳动。
4. 作品媒体进入视口时只做一次轻微显现，不自动轮播、不视差、不悬浮。
5. `prefers-reduced-motion: reduce` 下取消位移、显现和共享转场，仅保留即时状态变化。

动效参数应复用现有 `--ease`、`--t-1`、`--t-2`，除非验证后发现必要性，不新增时间令牌。

## 5. 内容与后台边界

余笺应作为独立内容类型实现，而不是把现有文章通过特殊分类伪装成余笺。这样文章的发布校验、搜索语义和 SEO 不会被混合载荷拖复杂。

建议的最小字段：

- `title`
- `slug`
- `type`
- `body_markdown`
- `excerpt`
- `published_at`
- `status`
- `media`
- `external_url`

后台编辑需要提供标题、类型、正文、摘要、媒体和外链字段；类型使用固定下拉选项。第一阶段不增加草稿协作、评论、点赞、统计和复杂作品画廊编辑器。

Markdown 正文仍是唯一真实数据源，渲染产物必须沿用现有清洗边界。媒体沿用现有上传路径隔离、尺寸约束和引用追踪规则。

## 6. 数据流与接口约束

新增公开接口应保持现有列表接口的分页载荷风格：

```json
{
  "items": [],
  "total": 0,
  "page": 1,
  "per_page": 20,
  "has_more": false
}
```

列表支持类型筛选和分页；详情按 slug 获取。公开载荷不暴露后台关键词、内部修订信息或未发布内容。首页「近笺」只请求所需数量，不复制完整列表逻辑。

前端新增独立 composable 管理余笺列表和详情请求，沿用现有模块级单例与并发去重模式；不要引入 Pinia/Vuex。

## 7. 非目标

- 不把余笺改造成社交时间线。
- 不让余笺与文章混排成首页主列表。
- 不增加新的主题色、阴影体系、圆角等级或背景纹理。
- 不在第一阶段加入评论、点赞、收藏、RSS 独立频道或复杂互动。
- 不为了余笺改写现有文章数据模型。

## 8. 验收标准

- 桌面端和窄屏端都能从一级导航进入余笺，当前入口有 `aria-current`。
- 首页出现 2–3 条「近笺」，不挤压最新文章的第一视觉层级。
- 类型筛选可通过 URL 分享、后退和刷新恢复。
- 日常、项目、作品、随想四类均能独立展示；作品/项目可展示媒体或外链。
- 列表和详情不出现卡片堆叠、无限滚动或社交计数。
- 启用减少动效后，页面仍然完整可用且无明显布局跳动。
- 后端、前端测试和生产构建通过，设计令牌与 `DESIGN.md` 保持同步。
